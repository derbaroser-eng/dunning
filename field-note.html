Three retries, then stop

An expired card and a €4 invoice do not need the same retry schedule. The decision engine reads one JSON event and prints one JSON decision. No network calls, no database, nothing to audit except the rules themselves.

Real output, customer id trimmed:

attempt 1, card_declined, €29
{"action": "retry", "retry_after_hours": 24, "email_template": "friendly_reminder", "escalate": false}

attempt 3, card_declined, €29
{"action": "retry", "retry_after_hours": 168, "email_template": "final_notice", "escalate": true}

attempt 1, expired_card
{"action": "no_retry", "retry_after_hours": null, "email_template": "update_payment_method", "escalate": true}

attempt 2, card_declined, €5
